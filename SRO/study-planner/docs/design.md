# Проектирование системы «Планировщик учебных задач»

## 1. Модель жизненного цикла

Для разработки проекта выбрана инкрементная модель жизненного цикла.

При такой модели приложение создаётся постепенно. Сначала реализуются основные функции, после чего добавляются дополнительные возможности.

Этапы разработки проекта:

1. Создание базового HTML-интерфейса.
2. Реализация добавления и отображения задач.
3. Добавление редактирования и удаления.
4. Добавление статусов и приоритетов.
5. Реализация поиска и фильтрации.
6. Добавление сохранения данных в Local Storage.
7. Проверка ввода и тестирование.

Инкрементная модель подходит для данного проекта, поскольку функциональность небольшого приложения удобно реализовывать и проверять поэтапно.

## 2. Архитектура приложения

Приложение состоит из трёх основных частей:

### Интерфейс

HTML отвечает за структуру страницы:

- заголовок;
- статистику;
- панель поиска и фильтрации;
- список задач;
- форму создания и редактирования задачи.

### Оформление

CSS отвечает за внешний вид приложения:

- расположение элементов;
- размеры;
- цвета;
- кнопки;
- карточки задач;
- адаптацию интерфейса.

### Логика

JavaScript отвечает за работу приложения:

- создание задач;
- изменение задач;
- удаление;
- изменение статуса;
- поиск;
- фильтрацию;
- сортировку;
- подсчёт статистики;
- проверку введённых данных;
- сохранение данных.

## 3. Структура данных

Основные данные хранятся в массиве `tasks`.

Каждая задача представлена объектом следующего вида:

    {
        id: 1,
        title: "Подготовить презентацию",
        subject: "Программирование",
        deadline: "2026-10-22",
        priority: "Высокий",
        status: "В процессе"
    }

Поля объекта:

- `id` — уникальный идентификатор;
- `title` — название задания;
- `subject` — учебный предмет;
- `deadline` — срок выполнения;
- `priority` — приоритет;
- `status` — состояние задачи.

## 4. Хранение данных

Для хранения информации используется Local Storage браузера.

После изменения списка задач массив преобразуется в строку JSON:

    JSON.stringify(tasks)

При запуске приложения данные считываются обратно:

    JSON.parse(localStorage.getItem("studyTasks"))

Это позволяет сохранять задачи после обновления и закрытия страницы без использования сервера и базы данных.

## 5. Основные модули программы

Логику приложения можно условно разделить на следующие модули:

1. Управление задачами
   - создание;
   - редактирование;
   - удаление;
   - завершение задачи.

2. Отображение
   - вывод списка;
   - отображение информации о задаче;
   - отображение статистики.

3. Поиск и фильтрация
   - поиск по названию и предмету;
   - фильтрация по статусу;
   - фильтрация по приоритету.

4. Хранение
   - запись массива в Local Storage;
   - восстановление массива при открытии страницы.

5. Проверка данных
   - проверка названия;
   - проверка предмета;
   - проверка срока.

## 6. Ключевые алгоритмы

### Добавление задачи

1. Пользователь вводит данные.
2. Программа получает значения полей.
3. Выполняется проверка обязательных полей.
4. Создаётся объект задачи.
5. Объект добавляется в массив `tasks`.
6. Массив сохраняется в Local Storage.
7. Список на странице обновляется.

### Поиск

1. Получается текст из строки поиска.
2. Программа перебирает массив задач.
3. Название и предмет переводятся в нижний регистр.
4. Выполняется сравнение с поисковым запросом.
5. Подходящие задачи отображаются пользователю.

### Фильтрация

Для каждой задачи проверяются выбранные пользователем параметры.

Если статус и приоритет соответствуют фильтрам, задача остаётся в отображаемом списке.

### Определение просроченной задачи

1. Получается текущая дата.
2. Получается срок задачи.
3. Сравниваются две даты.
4. Если срок меньше текущей даты и задача не выполнена, она считается просроченной.

### Сортировка

Задачи сортируются по сроку выполнения от ближайшей даты к более поздней.

## 7. Обработка ошибок

Перед созданием или изменением задачи проверяются обязательные поля.

Если название, предмет или срок не заполнены, операция не выполняется.

Вместо этого пользователь получает сообщение с описанием ошибки.

Также перед удалением используется подтверждение, чтобы уменьшить вероятность случайного удаления задачи.

## 8. Схема работы приложения

Пользователь
      ↓
HTML-интерфейс
      ↓
JavaScript
      ↓
Массив tasks
      ↓
Local Storage
      ↓
Обновление интерфейса

## 9. Вывод

Разработанная архитектура является простой и подходит для небольшого учебного приложения.

Использование HTML, CSS и JavaScript позволяет запускать проект непосредственно в браузере. Local Storage обеспечивает сохранение данных без отдельного сервера и базы данных.
